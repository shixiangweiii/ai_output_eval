## 二、分级问题清单

分级依据不是"严重程度"而是**"它使什么失效"**——这决定了修复顺序。

### A 类：使本次两份运行的横向对比无效（不改考卷也必须重跑）

#### A1. 两次运行在配置层面本就不可比，而 v4 的守卫按设计放行了

| 字段 | arag | dify |
|---|---|---|
| `exam_sha256` | `74b2892…` | `f0a4841…`（改目录名之前） |
| `corpus.relative_dir` | `…/2026-08-04-02-真多跳` | `…/2026-08-04-02`（**该目录已不存在**） |
| `score_threshold` | 无 | **`enabled=true, 0.55`** |
| `git.dirty` | false | **true** |
| `evaluator_script_sha256` | `eda66ae…` | `01da84a…` |
| Python | 3.12.10 | 3.14.2 |

关键的是 `score_threshold`：dify 请求 `top_k=20` 却只拿回中位 9 条，arag 无阈值拿回中位 14 条。**返回深度直接决定 recall@10**——这正是 v3 那次"0.1204 的差距里 77% 来自配置"的同型错误。

v4 的守卫（`retrieval_eval_v4.py:2303`）只在**同一 `backend_profile` 出现两种 `request_config`** 时报错，跨 profile 一律放行，理由是"不同产品请求体天然不同"。这个理由对 `search_method`、`reranking_model` 成立，但对 `top_k` / `score_threshold` / `reranking_enable` 这类**决定返回预算的旋钮**不成立——它们不是产品差异，是可调参数。

另外 `dataset_revision` 的校验是 `bool(args.dataset_revision)`（`retrieval_eval_v4.py:2692`），只判断"你有没有填字符串"。两份**不同的 corpus 快照**都填了 `2026-08-04-02`，标签没有和 corpus sha 绑定，等于没有校验。

**修**：
1. 守卫改为按语义字段跨 profile 对齐：抽取 `top_k`/`score_threshold*`/`reranking_enable` 做一致性检查，不一致时默认阻断，`--allow-config-diff` 才放行；
2. `dataset_revision` 与 `corpus` 段的 sha 集合一起哈希后写入 manifest，`--compare` 校验该派生值而非字符串；
3. dify 那份运行需在干净工作树 + 当前考卷（`74b2892…`）下重跑。

#### A2. `budget_claim_recall` 的预算网格同时对一个产品饱和、对另一个产品惰性

`char_budgets = [250, 500, 1000]`：

- 对 dify（top-10 共 325 字符）：预算 500 已覆盖 **153.8%** 的全部上下文 → 曲线 0.3963/0.4983/0.5204，末端 0.5204 与 `k=20` 的 0.5204 完全相同，**指标惰性**。
- 对 arag（top-10 共 6046 字符）：预算 1000 只覆盖 **16.5%** → 曲线 0.165/0.2721/0.3435，而其无预算约束下的 `k=10` recall 是 0.6684，**整条曲线都在深度截断区**。

**同一网格在同一次对比里同时犯了 v3 的错（预算过大导致惰性）和它的反面（预算过小导致失真）。** 于是两项主指标给出相反排名（claim recall arag 胜，budget recall dify 胜），而"五项主指标并列、不加权汇总"意味着没有裁决规则——本次比较在方法论上**无结论**。

二次反思时我修正了第一版的说法：这个指标本身**不是错的**，"用 500 字上下文能拿到多少证据"是一个真实且有意义的问题，返回 688 字符块的后端确实更浪费上下文。错的是三件事——(a) 把它叫作"分段中立"，它实际是**分段敏感、方向与 claim recall 相反**；(b) 预算网格没有按被测块尺寸校准；(c) 报告里不打印块尺寸分布，读者无从判断这个数字意味着什么。

**修**：预算网格按被测对象自适应（例如取各后端 top-`primary_k` 上下文总量中位数的 {10%, 25%, 50%, 100%} 或统一取 [1000, 4000, 16000] 这种贴近真实上下文窗口的量级）；报告新增块尺寸分布与 top-k 上下文总量；把"分段中立"的措辞改为"上下文预算受限视图"。

### B 类：使这份考卷**永远**得不出显著结论（必须改考卷）

#### B1. cluster 结构让统计推断先天失效

6 个簇，其中两个占 35/49 题。后果有两层：

- **推断层**：整簇符号翻转只有 2⁶ = 64 种符号向量，**最小可达 p = 0.0307**，Holm×3 后 **0.0921**。也就是说，**无论两个产品差多少，`--compare` 在 α=0.05 下永远不可能显著**。这不是"样本不够"，是检验统计量的支撑集不含 0.05 以下的区域。
- **估计层**：CI 由两个巨簇是否被抽中主导，arag 的 0.6684 CI 跨到 [0.4083, 0.7532]，与 dify 的 [0.2500, 0.5834] 大面积重叠。

`audit_exam.py` 的 G9（`评测脚本/考卷生成/audit_exam.py:308`）只卡"每簇 ≥3 题、且不止一个簇"。**聚类 bootstrap 的方差由簇的*个数*决定，不由簇的大小决定**——这一点 CLAUDE.md 写对了，但闸门里没有落实为"簇数下限"和"单簇占比上限"。

**修**：G9 增加两条：`簇数 ≥ 10`（可达 p 下界 ≈ 2/2¹⁰ ≈ 0.002）、`单簇计分题占比 ≤ 20%`。A/B 族按 section 主题（抗凝强度 / 肾功能 / 围手术期 / 出血识别…）再切分即可拿到 12–14 个簇，不需要新增题目。

#### B2. 桥接召回恒为 0：指标测的是被测对象接口契约之外的能力

考卷用 G10（桥接文档不得出现端点实体）+ G13（桥接文档不得进入题面 lexical top-10）**保证了桥接文档从题面不可达**；评测契约是"一条 query → 一次检索"。二者叠加，单轮检索器在信息上无法命中桥接文档。

第一版我写"对被测对象无解"，二次反思后要更准确：

- G13 只用 char-bigram BM25 证明了**词面不可达**；这两次运行补上了**语义/混合检索也不可达**的实证——桥接文档进入 top-10 仅 2/24 与 0/24，桥接 claim 命中 0/24 与 0/24。
- 这**不等于考卷出错了**。如果对比集里有做查询改写、实体扩展、GraphRAG 或多轮检索的产品，`bridge_claim_recall` 就是一个极好的能力探针，而且它天然抗刷分。
- 问题在于：**面对两个单轮检索 API，它是一个方差为 0 的常数**，占用了五分之一的主指标位，且没有任何机制说明这件事。

三个具体缺陷：

1. **报告的自动结论是同义反复**。`retrieval_eval_v4.py:2107` 在落差大时打印"说明多跳设计成立：检索器能找到两端，但接不上中间那份材料"。"多跳设计成立"由 G10/G13 先验保证，**不需要运行时数据来证明**；而落差大**不能**推出关于产品能力的任何结论。判据只在一个方向上有效（落差小 ⇒ 设计失败，这一支代码写对了），反方向被误写成了肯定性结论。
2. **结构天花板从不披露**。12 道链式题占计分题 24.5%，其 claim recall 上限是 2/3 或 2/4，`complete_evidence_chain` 结构性为 0。全卷天花板因此是 0.8980 / 0.7551，而报告把 0.6684 摆在隐含满分 1.0 旁边。
3. **天花板会反向惩罚**。dify 有 **5/12** 链式题已经打到结构上限（arag 3/12）——它把能拿的全拿了，仍然只记 0.5，还拉低主指标。

**修**（三选一，建议同时做 1 和 3）：
1. 报告与 summary 中显式计算并打印结构天花板，主指标改为"占可达上限的比例"或并列呈现；
2. 若继续把 `bridge_claim_recall` 放在主指标位，需在 manifest 中记录被测后端是否声明支持多轮/查询扩展；对单轮后端自动降级为诊断项；
3. 把 `retrieval_eval_v4.py:2107` 的大落差分支改为中性措辞，例如"本次桥接文档不可达（进入 top-k 次数 X/N），该读数无法区分产品能力"。

#### B3. `abstention_auc` 是一个有效样本量为 3 的主指标

3 道不可答题，落在 2 个簇。两个 AUC 的 CI 都跨过 0.5（一个上界直接到 1.0）。更糟的是 `v4_q042`（"澜川普惠金融的评分卡自动通过线定在多少分？"——语料外实体、语料内话题）在两个后端的 top_score 都贴近可答题上限（0.9922 / 0.9234），**单点主导整个 AUC**。

另有同质性问题：arag 无阈值、空响应率 0.0，dify 因 `score_threshold=0.55` 空响应率 0.3333。`_abstention_score`（`retrieval_eval_v4.py:1475`）把空响应记为 `-inf`，这在同一次运行内是自洽的，但**跨后端比较时，AUC 一半来自"是否配置了阈值"这个人为选择**，而不是模型的置信度分离能力。

**修**：不可答题扩到 ≥12 道、覆盖 ≥4 个簇，并按类型分层——(a) 语料外实体、(b) 实时/时效数据、(c) 语料内主体但语料未记载的属性；报告分层给出 AUC。在 A1 的配置对齐没做到之前，`abstention_auc` 不应进入跨产品结论。

### C 类：使指标读数失真（改语料）

#### C1. 兄弟文档共享逐字样板，污染了 `document_recall` 与 `hard_negative_intrusion`

A 族每篇 8051 字符，**只有约 680 字符（8.4%）是本篇独有**，35 个段落在 5 篇里逐字相同；篇内还有重复（90 段中仅 58 段唯一）。

二次反思时我调整了第一版的判断：**相似本身是设计意图**（"兄弟文档判别"就是这份考卷的主题之一），问题不在"相似"，在"**逐字相同**"。二者的差别是可测量的：

- 逐字相同的段落让检索器命中任意一篇兄弟文档都算 `document_recall` 命中 → arag 0.7959 / dify 0.8776 的文档召回中，相当部分由 5 篇共有的样板文赚得。实测 **arag 返回的字符里 84.2% 是跨文档逐字重复文本**。
- `hard_negative_intrusion` 0.7 / 0.6 同理——它现在更多在量**语料的自我重复度**，而不是检索器的判别力。
- 近重复块在不同向量库中的去重、打分、MMR 策略差异极大，这本身就在产品间引入了与检索能力无关的差异。

改成"主题结构相同、逐句措辞各异"就能保住难度、去掉噪声。

#### C2. 信噪比过低，claim 匹配退化成"有没有精确命中那一句"

每篇约 90 段中只有约 10 段承载事实，且事实就是一整句 = 一个 span。于是"命中文档但没命中 claim"高达 18 例（arag）/ 48 例（dify）——检索器找对了文档、返回的是样板段落。**在正确文档内部选中哪个块，很大程度上是在 12 个近似等价的块里掷骰子**，这部分方差直接叠加到主指标上，稀释了本来要测的产品差异。

#### C3. 语料排版与 Dify 父子分段耦合，直接造成了 A2 的预算倒挂

这是二次反思新增的因果链，第一版没连起来：

语料每段以空行分隔、事实句自成一段 → Dify 的父子分段按空行切分 → **父块 = 标题行 + 一个段落 ≈ 36 字符**（原始响应中 `segment.content` 为 `"3. 肾功能与剂量调整\n达比加群在肌酐清除率低于 50 mL/min 时必须减量，不得维持原剂量。"`，`word_count: 49`）→ "父子分段"名存实亡，父块几乎等于子块 → top-10 上下文只有 325 字符 → 预算 500 对它完全惰性。

这**不是 profile 的 `field_map` 配错了**（读 `segment.content` 是对的，`child_chunks` 本就不该用），而是**语料格式与被测系统的切分策略产生了退化交互**。结论：语料修复和预算校准必须一起做，单修一头无效。

#### C4. 语料生成侧缺一道重复度闸门

现有 G1–G13 覆盖了 span 唯一性、span 间距、桥接隔离、链证据异质性等，**唯独没有一道闸门管"跨文档逐字重复率"和"篇内逐字重复率"**。C1/C2 能溜到线上运行才被发现，本质是生成管线少了这道自检。

**建议新增 G14（语料冗余闸门）**，在 `audit_exam.py` 或 `synthesize_corpus.py` 出口处执行：
- 任意两篇文档的逐字相同段落占比 ≤ 15%；
- 篇内逐字重复段落数 = 0；
- 每篇的"承载事实段落 / 总段落"≥ 0.25。

### D 类：脚本健壮性与口径一致性（改脚本，风险低）

#### D1. 请求出错静默记 0，且 `run_status` 仍是 `completed`

`evaluate_exam` 中 `request_error` / `response_schema_error` 的题不带 `metrics`，`_metric_value`（`retrieval_eval_v4.py:1446`）回退 `0.0` 后照常进入主指标；`run_status` 无条件设为 `"completed"`（`retrieval_eval_v4.py:2685`）；`comparison_eligible` 也不看错误率。

二次反思：把出错题记 0 **不一定错**——可用性本就是检索质量的一部分，这是一个可辩护的口径。真正的缺陷是**口径不一致**：`--compare` 明确排除了在任一运行中出错的题（`compare_runs` 的 `excluded`），而单次运行的 headline 把它们算成 0。同一套数字在两个入口下含义不同。

**修**：二选一并写进 metrics 版本说明——(a) 两处都排除，headline 增加 `num_excluded_errors` 字段；或 (b) 两处都记 0，但 `run_status` 在错误率 > 0 时降级为 `completed_with_errors`，并作为 `comparison_blocker`。

这两次运行成功率都是 1.0，所以未被暴露；一次网络抖动就会被读成"能力下降"。

#### D2. 五项主指标里两项进不了 `--compare`

`HEADLINE_PAIRED_FIELDS`（`retrieval_eval_v4.py:2230`）只有 `claim_recall` / `complete_evidence_chain` / `budget_claim_recall` 三项。`abstention_auc` 与 `bridge_claim_recall` **没有任何配对检验**，只在 `runs[]` 里被列为参考值。另外 Holm 只在同一指标内部的两两比较之间做，**未跨指标校正**——N-way 比较下多重性会被低估。

**修**：`bridge_claim_recall` 可直接按题配对（它是每题的比值）；`abstention_auc` 是全局量，需要用簇级 bootstrap 求两个运行 AUC 之差的 CI。Holm 的校正族改为"指标 × 两两配对"的全集。

#### D3. `off_target_chunk_rate` 不区分"错文档"与"对文档错章节"

`compute_metrics_at_k`（`retrieval_eval_v4.py:1146`）只按 `document_key` 判定离题。在这份语料上，主要失败形态恰恰是"文档对、章节错"（18/48 例），这个指标看不见。建议拆成 `off_target_document_rate` 与 `off_section_chunk_rate` 两个诊断项。

## 四、明确**不是**问题的部分（避免过度修正）

- **同一张图片 URL 出现在多篇兄弟文档中**（`Flowchart_Process.svg` 在 A3/A4，`Network_architecture_2levels.png` 在 B1/B2）：这是 `shared_url` 标签声明的刻意设计，评测器靠 `document_key` 约束正确处理，测的是文档消歧而非图像理解——设计正确，只是名字 `asset_reference_retrieval` 容易被误读。
- **claim 采用子串匹配、因而对分块边界敏感**：已在 CLAUDE.md 中明示，并已用 `document_recall` 与预算曲线做旁证，属于已知且已披露的取舍。
- **哨兵桶**：两个后端 4/4 全过，证明链路、鉴权、文档名映射、归一化都没坏——这正是哨兵该起的作用。
- **文档名闸门（exit 4）与凭据不落盘**：设计与实现都正确。
- **G11 / G13**：上一版"假多跳"（同一句话换个数字出现在三篇兄弟文档里）已被彻底挡住，难度校准显示 `g13_bridge_directly_reachable` 与 `g13_endpoint_unreachable` 均为空。这一层是有效的。
- **`normalize_text` 与 v3 逐字节一致并有单测锁定**：应继续保持。

## 五、修复路线（按依赖顺序，不按严重度）

**第 0 步（不改任何东西，先止损）**：把这两份运行标注为"配置不可比、仅供诊断"，不要据此写产品结论。dify 那份的 `exam_sha256` 已是历史版本，本就无法进入 `--compare`。

**第 1 批 — 让考卷具备产出结论的能力（改考卷 + 闸门，无需重跑）**
1. B1：A/B 族按 section 主题重切簇 → 12–14 簇；G9 增加"簇数 ≥10、单簇占比 ≤20%"。
2. B3：不可答题扩到 ≥12 道、≥4 簇、分三型。
3. B2：`build_exam.py` 输出结构天花板并写入 `exam_meta`；报告并列展示"实测值 / 可达上限"。

**第 2 批 — 让指标读数可信（改脚本）**
4. A2：预算网格自适应；报告新增块尺寸与 top-k 上下文总量分布；措辞去掉"分段中立"。
5. A1：配置守卫改为按语义字段跨 profile 对齐；`dataset_revision` 与 corpus sha 绑定。
6. B2-3：`retrieval_eval_v4.py:2107` 大落差分支改中性措辞。
7. D1/D2/D3：口径一致性、配对检验补齐、离题率拆分。

**第 3 批 — 让语料不再制造噪声（重生成 + 重灌库）**
8. C1/C2/C4：兄弟文档改为"结构相同、措辞各异"，篇内零逐字重复，事实段占比 ≥25%；新增 G14。
9. C3：与第 4 步一起验证——语料改版后重新确认 Dify 父块尺寸是否恢复到有意义的量级。

**第 4 批 — 重跑**
10. 在干净工作树、对齐 `top_k`/`score_threshold`、同一 `exam_sha256` 下重跑两个后端，再做 `--compare`。

> 注意第 3 批会改变 corpus SHA-256 → 必须重建考卷 **且重新灌 KB**，且会使当前所有归档运行失去可比性。建议第 1、2 批先落地并重跑一轮拿到基线，再动语料。
