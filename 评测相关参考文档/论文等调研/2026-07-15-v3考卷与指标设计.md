# 检索评测 v3：考卷、指标与运行协议

## 1. 定位

v3 是基于现有 10 篇语料的检索回归评测，不是独立盲测集。它只评估检索系统为下游问答准备证据的能力，不评估最终答案、推理正确性、拒答或工具调用。

新链路与 v2 完全隔离：v3 考卷位于 `评测考试/考卷-v3/`，由 `评测脚本/retrieval_eval_v3.py` 执行，结果写入 `评测考试/考试结果-v3-<backend>/`。旧考卷、旧脚本和历史结果不参与 v3 Schema 校验。

## 2. 考卷构成

`考卷-2026-07-15-03` 共 40 题：36 道计分题和 4 道无答案边界诊断题。

| 主类型 | 数量 | 目的 |
|---|---:|---|
| single_doc_fact | 8 | 建立单文档基础能力基线 |
| single_doc_multi_claim | 6 | 检查同文档多原子事实覆盖 |
| cross_doc_compare | 8 | 检查双文档比较和口径消歧 |
| cross_doc_chain | 8 | 检查三文档完整证据链 |
| disambiguation_hard_negative | 3 | 检查相似概念、旧口径和表面数字干扰 |
| asset_reference_retrieval | 3 | 检查共享图片 URL 的逐来源召回 |
| unanswerable_diagnostic | 4 | 收集无答案查询的返回深度和最高分，不计主分 |

正式题难度分布为简单 8、中等 14、困难 14。全卷含 73 个互不复用的原子 claim；每篇语料贡献 7–8 个 claim。至少 12 题满足低词面重合约束，至少 8 题带显式硬负例。

## 3. v3 标注协议

每道计分题包含 `claims[]`。一个 claim 只表达一个事实，使用以下字段：

```json
{
  "id": "v3_q001_c1",
  "kind": "text",
  "source_document": "01_急性冠脉综合征院内诊疗路径.md",
  "section": "3. 诊断流程与分诊决策",
  "accepted_spans": ["患者到达急诊，10 分钟内必须完成首份 12 导联心电图"]
}
```

命中条件是：检索 chunk 的 `document_name` 与 `source_document` 完全相同，并且归一化后的 chunk 内容包含任一归一化 `accepted_span`。文本 span 归一化后必须为 8–120 字符；资产 URL 不受该长度限制。

`negative_evidence[]` 使用相同的文档与 span 定位方式，但只用于硬负例侵入诊断。`reference_answer` 与 `evidence_chain` 不进入自动评分。

考卷通过 `exam_meta.corpus` 记录相对语料路径、快照 ID 和逐文件 SHA-256。默认情况下，任一哈希漂移都会阻断运行；强制使用 `--allow-corpus-drift` 后，结果必须标记为不可比较。

## 4. 三项主指标

正式口径固定使用生产响应顺序和 Top-5，不允许通过重排参数改变主分语义。

### Query Macro Claim Recall@5

先计算每题命中 claim 数除以该题 claim 总数，再对 36 道计分题等权平均。普通请求错误按该题零分计。

### Complete Evidence Chain Rate@5

Top-5 命中一题全部必需 claim 才算该题证据链完整，最终报告完整题目的比例。

### Novel Claim Rank Score@5

每个 claim 只按第一次命中排名计分，重复 chunk 不重复贡献：

```text
NCRS@K(q) = Σ_c I(r_c ≤ K) / log2(r_c + 1) / |C_q|
```

其中 `r_c` 是 claim 的首次命中排名，未命中贡献零。该指标同时奖励较早出现和不同 claim 的新增覆盖。

三项主指标分别报告 10,000 次查询级 bootstrap 的 95% 置信区间，固定随机种子为 `20260715`。v3 不生成加权综合总分。

## 5. 诊断指标

除主指标外，脚本报告：

- Claim 微平均召回、文档召回；
- @1/@3/@5/@10 曲线；
- 1000/2000/4000 归一化字符预算下的 Claim Recall；
- 硬负例侵入、重复文档、响应深度不足、资产来源覆盖；
- 请求错误、延迟 p50/p95、排名异常；
- 按难度、主类型、标签和 GT 文档数拆分；
- 在所有 chunk 都有数值相关度时，附加 relevance 重排反事实，不改变正式主分。

4 道无答案题仅记录 `returned_count`、`highest_relevance_score`、来源文档和重复率。没有后端专属阈值校准前，不把“返回非空”直接判为失败。

## 6. 运行与比较

```bash
.venv/bin/python 评测脚本/retrieval_eval_v3.py --validate-only

RETRIEVAL_COOKIE=... RETRIEVAL_XSRF_TOKEN=... \
  .venv/bin/python 评测脚本/retrieval_eval_v3.py \
  --backend arag --request-k 10 --eval-k 1,3,5,10 --primary-k 5

RETRIEVAL_COOKIE=... RETRIEVAL_XSRF_TOKEN=... \
  .venv/bin/python 评测脚本/retrieval_eval_v3.py \
  --backend dify --graph-search --request-k 10 \
  --score-threshold-enabled

RETRIEVAL_COOKIE=... RETRIEVAL_XSRF_TOKEN=... \
  .venv/bin/python 评测脚本/retrieval_eval_v3.py \
  --backend dify --dify-search-method coverage_search --request-k 10 \
  --score-threshold-enabled --out-dir 评测考试/考试结果-v3-dify-new

.venv/bin/python 评测脚本/retrieval_eval_v3.py \
  --compare path/to/results_a.json path/to/results_b.json
```

Dify 的 `--request-k` 会真实写入请求体；aRAG 接口没有 K 参数，Manifest 会记录 `unsupported_by_backend` 和实际响应深度。

`--score-threshold-enabled` 用于精确复现 Dify 控制台请求；未同时传入 `--score-threshold` 时，请求体发送 `score_threshold: null`。如果传入数值阈值，脚本会自动启用该开关并记录到 Manifest。

`--dify-search-method coverage_search` 用于覆盖索引策略，请求体发送 `search_method: coverage_search`，并将 `reranking_mode`、`weights`、`graph_search` 置为 `null`。该模式不能与 `--graph-search` 同时启用；默认值仍为 `hybrid_search`。

配对比较要求两次运行均为 completed/full、同一考卷哈希、同一语料快照、同一题目集合和主 K。比较产物报告 Right-Left 差值、配对 bootstrap 95% CI 和双侧随机置换检验结果。

每次正式运行生成 results、summary、report、manifest 四类产物。Manifest 记录后端、dataset、检索配置、版本、Git 状态和安全声明；Cookie、CSRF/XSRF Token 与请求头绝不落盘。
